# Git Commit AI Agent 全流程改造手册（本地门禁 + 自动提交推送）

> 目标：指导任意 AI Agent 在**目标仓库**内自动完成以下动作：
> 1) 自动安装/更新 `git-commit-ai` skill；
> 2) 配置本地 hooks 门禁（含已有 hooks 兼容）；
> 3) 无感触发 skill 生成规范 commit 信息并提交；
> 4) 自动推送到远端分支。

## 1. 适用范围

- 适用 Agent：Claude Code / Codex / Gemini CLI / Kimi CLI / Cursor / Aider。
- 适用系统：macOS / Linux（Windows 可参考等价 PowerShell 实现）。
- 依赖：`git`、`node`、可用远端仓库权限（push）。

## 2. 关键约束（Agent 必须遵守）

1. 始终在目标仓库根目录执行（`git rev-parse --show-toplevel`）。
2. 默认 `AI_POLICY=auto`：仅当检测到 AI 使用时强制 `AI-Info`。
3. 不要跳过 hooks（禁止 `--no-verify`）。
4. 推送默认非强推（禁止 `--force` / `--force-with-lease`，除非明确授权）。

## 3. 标准输入变量

建议 Agent 在执行前准备以下变量（可用默认值）：

```bash
TARGET_REPO="${TARGET_REPO:-$(pwd)}"
AGENT_NAME="${AGENT_NAME:-codex}"       # claude-code|codex|gemini-cli|kimi-cli|cursor|aider
AI_POLICY="${AI_POLICY:-auto}"          # auto|always|never
AUTO_PUSH="${AUTO_PUSH:-1}"             # 1=提交后自动推送，0=只提交
COMMIT_TYPE="${COMMIT_TYPE:-chore}"     # feat|fix|docs|style|refactor|perf|test|chore|ci|build|revert|wip|ai
COMMIT_SCOPE="${COMMIT_SCOPE:-}"
COMMIT_MSG="${COMMIT_MSG:-update changes}"
COMMIT_BODY="${COMMIT_BODY:-}"
SKILL_REPO_URL="${SKILL_REPO_URL:-https://github.com/rdealist/git-commit-ai}"
```

## 4. 一次性改造流程（可直接执行）

### 4.1 安装或更新 skill（全局）

优先使用官方安装脚本（自动处理多 Agent 路径）：

```bash
curl -fsSL "https://raw.githubusercontent.com/rdealist/git-commit-ai/main/install/install.sh" \
  | bash -s -- --global --agent "${AGENT_NAME}"
```

如果不能访问网络，使用本地 skill 仓库路径执行：

```bash
# 假设 LOCAL_SKILL_REPO 指向 git-commit-ai 仓库根目录
bash "${LOCAL_SKILL_REPO}/install/install.sh" --global --agent "${AGENT_NAME}"
```

### 4.2 定位 skill 入口脚本

```bash
find_skill_script() {
  local candidates=(
    "$HOME/.claude/skills/git-commit-ai/scripts/git-commit-ai.js"
    "$HOME/.codex/skills/git-commit-ai/scripts/git-commit-ai.js"
    "$HOME/.codex/git-commit-ai/scripts/git-commit-ai.js"
    "$HOME/.config/codex/skills/git-commit-ai/scripts/git-commit-ai.js"
    "$HOME/.gemini/skills/git-commit-ai/scripts/git-commit-ai.js"
    "$HOME/.config/agents/skills/git-commit-ai/scripts/git-commit-ai.js"
    "$HOME/.agents/skills/git-commit-ai/scripts/git-commit-ai.js"
    "$HOME/.kimi/skills/git-commit-ai/scripts/git-commit-ai.js"
    "$HOME/.cursor/skills/git-commit-ai/scripts/git-commit-ai.js"
    "$HOME/.aider/skills/git-commit-ai/scripts/git-commit-ai.js"
  )

  local p
  for p in "${candidates[@]}"; do
    if [ -f "$p" ]; then
      echo "$p"
      return 0
    fi
  done
  return 1
}

SKILL_SCRIPT="$(find_skill_script)" || {
  echo "[ERROR] 未找到 git-commit-ai 脚本，请检查安装" >&2
  exit 1
}
```

### 4.3 在目标仓库安装本地门禁 hooks

```bash
cd "${TARGET_REPO}"
node "${SKILL_SCRIPT}" --install-hook --ai-policy "${AI_POLICY}"
```

该命令会完成：

- 安装 `prepare-commit-msg`：尝试补全 `AI-Info`。
- 安装 `commit-msg`：校验标题规范与 AI 字段。
- 兼容已有 hooks：
  - 若已有 hook 非 git-commit-ai 生成，会备份为 `*.legacy`；
  - 新 hook 会先执行 legacy，再执行 git-commit-ai 逻辑。

### 4.4 改造结果验收

```bash
# 1) hook 是否存在
HOOKS_DIR="$(git config --get core.hooksPath)"
if [ -z "$HOOKS_DIR" ]; then
  HOOKS_DIR=".git/hooks"
fi
[ -x "$HOOKS_DIR/prepare-commit-msg" ]
[ -x "$HOOKS_DIR/commit-msg" ]

# 2) 门禁策略
git config --local --get commitai.aiInfoPolicy

# 3) hook 是否由 skill 管理
grep -q "Generated by git-commit-ai skill" "$HOOKS_DIR/prepare-commit-msg"
grep -q "Generated by git-commit-ai skill" "$HOOKS_DIR/commit-msg"
```

## 5. 日常“无感”提交 + 推送流程（Agent 执行模板）

> 推荐统一调用 `node "$SKILL_SCRIPT" ...`，比依赖 `/skill:` 指令解析更稳定。

```bash
cd "${TARGET_REPO}"

# 1) 暂存改动
git add -A

# 2) 生成并执行提交（skill 内部会调用 git commit）
ARGS=(--type "$COMMIT_TYPE" --message "$COMMIT_MSG")
[ -n "$COMMIT_SCOPE" ] && ARGS+=(--scope "$COMMIT_SCOPE")
[ -n "$COMMIT_BODY" ] && ARGS+=(--body "$COMMIT_BODY")

node "${SKILL_SCRIPT}" "${ARGS[@]}"

# 3) 自动推送（可关闭）
if [ "${AUTO_PUSH}" = "1" ]; then
  BRANCH="$(git branch --show-current)"

  # 无 upstream 时自动绑定 origin/<branch>
  if git rev-parse --abbrev-ref --symbolic-full-name "@{upstream}" >/dev/null 2>&1; then
    git push
  else
    git push -u origin "$BRANCH"
  fi
fi
```

## 6. 针对不同 Agent 的触发建议

- Claude Code / Codex / Gemini CLI / Kimi CLI：
  - 可用 `/skill:git-commit-ai ...`。
  - 但自动化场景仍建议直接 `node "$SKILL_SCRIPT" ...`（更可控）。
- Cursor / Aider：
  - 直接 `node "$SKILL_SCRIPT" ...`。

## 7. 失败处理策略（Agent 必须实现）

### 7.1 提交被门禁拒绝

1. 读取报错信息（如标题不规范、缺失 `AI-Info` 字段）。
2. 自动修正 commit 参数后重试一次。
3. 若仍失败，输出错误并停止，不要绕过 hook。

### 7.2 push 失败

- 若提示无权限：停止并反馈权限问题。
- 若提示非 fast-forward：
  1) `git pull --rebase`；
  2) 处理冲突；
  3) `git push` 重试。

## 8. 回滚方案（必要时）

```bash
cd "${TARGET_REPO}"
HOOKS_DIR="$(git config --get core.hooksPath)"
if [ -z "$HOOKS_DIR" ]; then
  HOOKS_DIR=".git/hooks"
fi

for h in prepare-commit-msg commit-msg; do
  if [ -f "$HOOKS_DIR/$h.legacy" ]; then
    mv "$HOOKS_DIR/$h.legacy" "$HOOKS_DIR/$h"
  fi
done

git config --local --unset commitai.aiInfoPolicy || true
```

## 9. Agent 执行完成判定（Definition of Done）

满足以下全部条件才算完成：

1. `git-commit-ai` skill 已安装并可调用。
2. 目标仓库存在可执行的 `prepare-commit-msg` 与 `commit-msg` hook。
3. 现有 hooks（如有）已被兼容（`*.legacy` 可追溯）。
4. 一次真实提交成功，且提交信息符合规范（含/不含 `AI-Info` 与策略一致）。
5. `AUTO_PUSH=1` 时，提交已成功推送到目标分支。
